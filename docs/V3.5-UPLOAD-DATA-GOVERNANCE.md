# V3.5 同事上傳資料治理

更新日期：2026-09-10

狀態：T6.3～T6.8 已完成，待正式環境確認主檔後開放同事使用

## 目的

同事上傳頁應負責把 GoWarehouse 匯出資料安全送入中台，不應要求同事自行記憶並輸入貨主或倉庫名稱。系統需優先使用匯出檔的可靠欄位，自動判斷證據不足時改由受控選單確認。

## 現況與風險

- 訂單上傳目前要求自由輸入品牌／貨主。
- 訂單資料使用「貨主＋訂單編號」識別；若貨主輸入不同，同一張訂單可能被視為另一筆資料。
- 倉庫只在來源檔具有倉庫欄位時保存，其他檔案目前無法完整納入倉別統計。
- 自由文字會產生錯字、簡稱與正式名稱並存，造成貨主拆分、數字失真及日後清理困難。

## GoWarehouse 匯出欄位能力

本表只記錄欄位是否存在，不保存原始客戶內容、真實訂單編號或個資。

| 資料類型 | 貨主欄位 | 倉庫欄位 | 第一判斷方式 |
|---|---:|---:|---|
| 訂單 | 無 | 無 | 跨檔與商品主檔比對；不足時人工選擇 |
| 庫存 | 有 | 無 | 貨主自動；倉庫人工選擇 |
| 揀貨單 | 有 | 有 | 貨主與倉庫均自動 |
| 托運單 | 有 | 無 | 貨主自動；倉庫跨檔比對或人工選擇 |
| 進倉單 | 無 | 無 | 跨檔比對；不足時人工選擇 |
| 退貨單 | 無 | 無 | 訂單與商品比對；不足時人工選擇 |

## 目標資料模型

### 倉庫主檔

- 穩定的倉庫代碼。
- 正式名稱與可接受別名。
- 啟用／停用狀態。
- 首批建立淡水與汐止；未來新增倉庫不需修改程式。

### 貨主主檔

- 穩定的貨主代碼。
- 正式名稱、GoWarehouse 顯示名稱與別名。
- 啟用／停用及待確認狀態。
- 未知名稱只有在可靠來源欄位中出現時，才能自動加入待確認名單；人工自由文字不得建立正式貨主。

### 匯入批次

- 保存檔案雜湊、資料類型、辨識倉庫、辨識貨主、辨識方式與確認者。
- 每筆整理後資料保存穩定的倉庫及貨主識別，不以顯示名稱作唯一鍵。
- 保留撤銷、更正及重新匯入的稽核紀錄。

## 判斷順序

1. 使用來源檔中明確的貨主或倉庫欄位。
2. 使用已確認的訂單編號跨檔對照。
3. 使用無歧義的商品編號與貨主主檔對照。
4. 使用管理者已確認的別名及既有映射。
5. 仍無法判斷時，停止自動匯入並要求從受控選單選擇。

不得只依模糊名稱、單一關鍵字或未確認的推測直接建立正式歸屬。

## 同事上傳流程

1. 輸入上傳專用密碼。
2. 選擇資料類型及檔案。
3. 系統解析但尚不寫入正式資料。
4. 顯示辨識結果、資料筆數、未辨識項目及衝突。
5. 有缺漏時使用倉庫／貨主下拉選單補充。
6. 使用者確認後正式匯入。
7. 匯入結果顯示批次編號；管理者可撤銷或更正整批資料。

## 驗收標準

- 同事不能輸入任意貨主或倉庫名稱。
- 揀貨單的貨主與倉庫可自動辨識。
- 訂單檔沒有充分證據時不自行猜測貨主。
- 同一訂單更正貨主後不會留下另一筆邏輯重複資料。
- 同一檔案含多個貨主時可按實際貨主分開保存。
- 新增倉庫只需在管理設定新增，不需修改程式。
- 匯入預覽不顯示收件人、電話、地址或其他不必要個資。
- 每次匯入、撤銷與更正都有可追溯紀錄。

## 實作結果

- 管理者可在設定頁維護倉庫、貨主、別名及啟用狀態。
- 同事上傳改為「先預覽、後確認」；不再接受任意貨主或倉庫文字。
- 系統能依可靠來源欄位、訂單及商品既有對照自動辨識；無法判斷時要求選擇，互相衝突時禁止寫入。
- 每批資料保存辨識方式、確認時間與異動快照，可更正或整批撤銷。
- 重複訂單清理需先試算，再以明確確認文字執行；被清理內容保留於可回復的異動紀錄。
- 原始上傳檔與原始內容不保存於 GitHub，測試資料均已去識別化。

## 正式使用前檢查

1. 管理者確認淡水倉、汐止倉名稱與別名。
2. 管理者確認由可靠來源自動建立的待確認貨主，並補齊常用別名。
3. 先由管理者用一份檔案完成預覽、確認、批次更正與撤銷演練。
4. 上述項目完成後，再把上傳專用密碼交給同事。
