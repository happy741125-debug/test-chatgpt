## 階段二後續需求（已確認，尚未實作）

同事上傳頁目前已可匯入資料，但多倉與貨主歸屬仍需補強後，才適合擴大交由同事使用：

- 訂單匯出檔本身沒有貨主與倉庫欄位；目前由同事自由輸入貨主，輸入錯誤會造成同一貨主被拆分，並可能讓同一張訂單以不同貨主重複存在。
- 庫存匯出檔可讀取貨主，但沒有倉庫欄位。
- 揀貨單匯出檔同時具有貨主與倉庫，可直接自動辨識。
- 托運單可讀取貨主，但沒有倉庫；進倉單與退貨單均沒有貨主及倉庫。
- 後續應建立倉庫主檔及貨主主檔。檔案有可靠欄位時自動辨識；沒有可靠欄位時只能從受控下拉選單選擇，不得自由輸入。
- 正式匯入前應先顯示辨識結果、無法辨識項目及衝突警示；並提供整批撤銷與更正機制。

詳細設計與任務拆解見 `docs/V3.5-UPLOAD-DATA-GOVERNANCE.md`。

## 階段二指標定義

- 退貨率＝未取消的退貨件數 ÷ 未終止的揀貨總件數；沒有分母時顯示無資料，不以 0 取代。
- 托運檔不保存收件人、地址、電話、真實單號；只保存雜湊識別碼與統計欄位。
- 原始 Excel 不保存於系統；資料庫只保存分類、狀態、數量、日期與倉別等整理後欄位。
- 托運檔若沒有配達日，仍會納入累計配送摘要，但不會進入指定週次的週摘要。
