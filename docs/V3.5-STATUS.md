## 已完成

- T1.1：依汐止與淡水週報建立 KPI 對照表，原始週報未放入公開 repository。
- T3.1：資料匯入頁只保留資料類型、品牌／貨主、檔案上傳與單次結果。
- T3.2：成功匯入後自動開啟營運表現，GoWarehouse 摘要在該頁顯示。
- T4.1：介面統一使用「決策層／執行層」，資料庫代碼維持相容。
- T5.1：新增介面設定，可拖曳或用按鈕調整頁籤順序、設定登入預設頁；偏好只保存在目前瀏覽器。
- 開發環境允許依設定的中台網址連線，正式環境仍只允許 Render 中台來源。
- T1.2：支援進倉、退貨、揀貨、托運匯出檔，新增完成上架量、揀貨單／件數、退貨率、托運包裹與配送別摘要。
- T1.3：新增每週人工營運指標，可按倉別保存工讀時數、加工量、耗材、盤差與板位備註並查閱歷史。
- T4.2：每週營運檢討新增「執行層本週總結」，呈現營運量與情報領域、事件類型、狀態分布。
- T6.1：新增 `/upload` 同事專用上傳頁，頁面不顯示任何中台資料。
- T6.2：新增獨立上傳密碼；只允許上傳，不能讀取管理 API。
- T5.2：管理者可在中台內修改管理密碼；新密碼以安全雜湊保存，修改後舊密碼立即失效。
- T6.3：建立倉庫主檔，預設淡水倉與汐止倉，後續倉庫可由管理者新增、改名、設定別名與停用。
- T6.4：建立貨主主檔與別名；可靠來源發現的新貨主先標示待確認，不因人工輸入直接建立正式貨主。
- T6.5：依來源欄位、既有訂單與商品對照分層辨識貨主及倉庫；資料互相矛盾時停止匯入。
- T6.6：同事上傳頁移除貨主與倉庫自由輸入，未辨識時只能從已建立的受控選單補充。
- T6.7：所有同事上傳均先預覽辨識結果、筆數、缺漏與衝突，確認後才寫入資料庫。
- T6.8：管理中台提供批次更正、整批撤銷、稽核紀錄與重複訂單檢查／清理；清理前先顯示預估結果。

詳細設計與任務拆解見 `docs/V3.5-UPLOAD-DATA-GOVERNANCE.md`。

## 階段二指標定義

- 退貨率＝未取消的退貨件數 ÷ 未終止的揀貨總件數；沒有分母時顯示無資料，不以 0 取代。
- 托運檔不保存收件人、地址、電話、真實單號；只保存雜湊識別碼與統計欄位。
- 原始 Excel 不保存於系統；資料庫只保存分類、狀態、數量、日期與倉別等整理後欄位。
- 托運檔若沒有配達日，仍會納入累計配送摘要，但不會進入指定週次的週摘要。
